KAFEEN Planner - changelog
==========================

Newest first. Versions are MAJOR.MINOR.PATCH. Each entry lists what changed
for people using the tool, then notes for anyone working on the code.


2.0.28  2026-11-21  Merged main: S is 2 points, threaded server, --host
-------------------------------------------------

  (s) is worth 2 points (sizes 1, 2, 3, 5, 8), the server runs requests
  on their own threads (?debug=1 shows a request log), the Planner

2.0.27  2026-11-21  Print the Planner on one page
-------------------------------------------------
- New: a printer button next to the Planner's week control prints the
  period shown on one landscape page, or saves it as a PDF. Day columns
  with big day names; a Habits row with a tick box per habit due that
  day; a row per project with its tasks (tick box, effort, ★ for a top
  priority, done ones struck out); an empty Other row to write in. On the
  right: the week's number and dates, Top priorities with lines to add
  more, tasks planned for the week without a day, each habit's days,
  effort per project to fill in, and lines for notes. At the foot: Top
  lesson of last week and Top priority this week. Works on every level
  (a month prints its weeks). Follows the filters, the projects on the
  calendar, the work week and Show on hold. A busy week gets less room to
  write, then smaller type, so it always fits on one page.
- Code: page only (web/app.js printPlanner, printSheet, fitSheet;
  plannerShown shared with vPlanner; web/app.css .psheet and @media
  print). The sheet is built off screen, fitted, printed, then removed.

2.0.13 (on main)  2026-11-11  --host for a network server
-------------------------------------------------
- New: python planner.py --serve --host 0.0.0.0 serves the page to every
  machine on your network (for example a Linux box on your LAN), at

2.0.12 (on main)  2026-11-10  Fewer redraws
-------------------------------------------------
- Changed: the Planner views no longer redraw when the server's answer
  is the same as what is already shown (for example after a window

- Code: render() / unchanged() / state.shown / state.ctl in web/app.js.


2.0.11 (on main)  2026-11-09  Stability: threaded server, debug log
-------------------------------------------------
- Fixed: the server handled one request at a time, so a browser
  connection that stalled (or one slow request) froze the whole page.
  Requests now run on their own threads; a silent connection is dropped
  after 10 seconds, a bad Content-Length is refused with a message, and
  an unexpected error is answered as an error instead of dropping the
  connection. The listen queue is larger, so a burst of requests from
  the browser is no longer reset.
- New: open the page with ?debug=1 to see each request's time and any
  error in a small overlay (and the console), to help track down freezes.
- Code: ThreadingHTTPServer; request bodies are read before taking the
  server lock, and API work takes turns under it (TODAY and LOG_END are
  per-request globals). Tests cover a stalled connection, bad lengths
  and parallel requests.
